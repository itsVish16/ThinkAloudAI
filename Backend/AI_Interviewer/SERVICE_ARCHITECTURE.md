# AI Interviewer Service Architecture

This document provides a comprehensive overview of the `AI_Interviewer` service, detailing its responsibilities, directory structure, database schema, API endpoints, and event integration.

---

## 1. Responsibilities
The **AI Interviewer Service** is a real-time, WebRTC-powered voice AI microservice. Its primary responsibilities are:
- **Real-Time Voice Agent:** Conducts human-like, low-latency audio interviews using LiveKit, Speechmatics STT/TTS plugins, and a Featherless-powered LLM.
- **State Machine Routing:** Manages the logical flow of an interview (Audio Check -> Set Agenda -> Intro -> Resume Deep Dive -> Technical Assessment -> Behavioral -> QA -> Wrap-up) using a LangChain Agent Graph.
- **Transcript Analysis:** Automatically analyzes the entire interview transcript upon completion to generate highly detailed feedback, scoring the candidate on Technical Knowledge, Communication, and English proficiency.
- **Microservice Integration:** Validates JWTs against the `Scalable_User_Service`, stores local replicas of user profiles for foreign key constraints, and publishes completion events to a central Redis Event Bus so the User Service can update the candidate's skills and roadmap.

## 3. Database Schema
This service uses an asynchronous PostgreSQL database (Neon) mapped via SQLAlchemy.

### `user_profile_replica`
A local replica of the user to enforce Foreign Keys without making synchronous HTTP calls on every insert.
- `id` (String, PK) - Maps to `Scalable_User_Service` User ID.
- `username` (String)
- `email` (String)

### `interview_sessions`
Tracks the core metadata and transcript of a given interview.
- `id` (String, PK) - The LiveKit Room Name.
- `user_id` (String, FK)
- `candidate_name` (String)
- `stage` (String) - Current node in the LangGraph.
- `state_data` (JSON) - The raw transcript (`messages`).
- `created_at` / `updated_at` (DateTime)

### `interview_feedback`
Stores the post-interview analysis generated by the background LLM task.
- `id` (String, PK)
- `session_id` (String, FK) - Unique connection to `interview_sessions`.
- `technical_score` (Integer) - 0 to 100.
- `communication_score` (Integer) - 0 to 100.
- `english_score` (Integer) - 0 to 100.
- `strengths` (Text) - Detailed textual strengths.
- `weaknesses` (Text) - Detailed textual areas of improvement.
- `improvement_plan` (Text) - Actionable steps.
- `recommended_topics` (JSON) - Array of strings indicating topics to study.

*(Note: Additional supporting tables like `interview_questions` and `interview_responses` exist for granular tracking).*

## 4. API Endpoints

### `POST /api/token`
Generates a LiveKit JWT token to allow the frontend to connect to the WebRTC room.
- **Auth:** Required (Bearer Token)
- **Request Schema:**
  ```json
  {
      "room_name": "interview_1234",
      "interview_type": "swe"
  }
  ```
- **Response Schema:**
  ```json
  {
      "token": "eyJhbG...",
      "url": "wss://thinkaloudai-....livekit.cloud",
      "roomName": "interview_1234",
      "candidate": "vishalsaini16"
  }
  ```

### `GET /api/interview-types`
Lists all supported interview configurations.
- **Auth:** None
- **Response Schema:**
  ```json
  {
      "types": [
          {
              "id": "swe",
              "name": "Software Engineering",
              "description": "Technical interview focusing on programming..."
          }
      ]
  }
  ```

### `GET /api/interview/{room_name}`
Retrieves the full transcript, active stage, and generated evaluation feedback.
- **Auth:** Required (Bearer Token)
- **Response Schema:**
  ```json
  {
      "room_name": "interview_1234",
      "stage": "completed",
      "candidate_name": "vishalsaini16",
      "transcript": [
          {"role": "assistant", "content": "Hi, I am your AI Interviewer..."},
          {"role": "user", "content": "Hello!"}
      ],
      "evaluation": {
          "technical_score": 85,
          "communication_score": 90,
          "english_score": 80,
          "strengths": "...",
          "weaknesses": "...",
          "improvement_plan": "...",
          "recommended_topics": ["System Design", "Caching"]
      },
      "updated_at": "2026-06-20T17:30:00.000Z"
  }
  ```

## 5. Event Driven Architecture

### Consumes
- This service **does not natively consume Redis events**. It responds primarily to WebRTC voice streams via LiveKit and HTTP Requests.
- For Authentication, it "consumes" the `Scalable_User_Service` `/api/v1/users/me` endpoint synchronously to validate JWTs.

### Produces
- **Channel:** `interview_events`
- **Event Name:** `InterviewCompleted`
- **Trigger:** Fired by the `analysis.py` background task *after* the LLM has successfully scored the candidate and saved the `interview_feedback` to the database.
- **Payload Schema:**
  ```json
  {
      "event": "InterviewCompleted",
      "data": {
          "interview_id": "interview_1234",
          "user_id": "1",
          "domain": "swe",
          "overall_score": 85
      }
  }
  ```
- **Consumer:** The `Scalable_User_Service` (`app/services/event_consumer.py`) listens to this payload to augment the candidate's `user_skills` table and log a `LearningEvent`.
